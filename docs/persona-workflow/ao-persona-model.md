# AO / Persona Routing Model

## Personas

The Security Campaign (and the wider DARKSWORD project) routes work through named personas, each representing a different analytical lens. A lesson or task can have a **primary** and **secondary** persona.

| Persona | Lens |
|---|---|
| ARCHITECT | Operating model, framework interpretation, system design |
| AUDITOR | Evidence standards, control mapping, compliance interpretation |
| SCRIBE | Documentation, data organization, analyst-note synthesis |
| SENTINEL | Log/traceback verification, technical failure diagnosis |
| RECON | Research, sourcing, external intelligence gathering |

## Standing Rules

- **AO remains the only approval authority**, regardless of persona route. Personas analyze and recommend; they do not self-approve.
- **Approval is per-action, never blanket.** A prior approval does not generalize to a later, different action.
- Cowork personas (via subagents or role framing) can propose and draft; AO reviews before anything ships.
